# 数据与实验设计

## 1. 研究问题与假设

研究问题：在多轮对话检索中，利用历史对当前问题进行改写，能否改善证据检索与最终回答？改善是否值得额外的延迟和成本？

假设：对指代、省略和连续追问，忠实补全历史信息可改善检索；对话题切换或本已完整的问题，盲目引入历史可能造成偏差。实验需要同时报告收益与失败情况，不能预设改进必然有效。

## 2. 数据与语料

- **QReCC**：使用官方提供的对话、人工重写及答案等字段，保留原始 ID、划分和来源。QReCC 是英文数据；参考 [官方仓库](https://github.com/apple-aiml-research/ml-qrecc) 与 [原始论文](https://aclanthology.org/2021.naacl-main.44/)。
- **中文补充集**：从许可清晰的文档构建独立知识库与多轮问题，记录文档版本、证据位置、参考答案、问题类型和编写规则。中文结果单独报告，不能视作 QReCC 的结果。
- **规模策略**：先验证数据下载、许可、文档可获取性和资源需求，再构建可复现的小规模语料与评测集。完整 QReCC 检索语料规模较大，子集结论不能声称代表完整开放域设置。

数据清单记录来源 URL、下载日期、许可、版本或哈希、筛选规则、文档数量、问题数量和随机种子。任何缺失或无法获得的原文、证据和标注都计数报告，不静默丢弃。遵循原始官方划分；如需子采样，以会话为单位固定抽样，开发集用于选择策略，测试集只用于最终比较，避免同一会话跨集合。

### 证据与检索标签

先检查官方字段和语料的实际映射能力。按稳定的文档 ID、URL 或官方标注将参考来源映射到索引，记录映射方法和覆盖率；URL 级相关性只能支持文档级评测，不能假称具有片段级精确标签。若只有答案字符串命中，则将其标记为弱代理，说明误匹配和漏匹配风险。若没有可靠标签，则不报告精确的检索相关性指标，改用人工标注子集并说明覆盖范围。

子集语料应按事先固定规则从可用来源构造，并包含合理的非相关文档；不能针对每条测试问题只放入其答案文档。若因资源限制采用答案来源构成候选池，应明确这是受限候选池评测，单独报告构建过程、覆盖率和限制，不能与完整语料检索直接比较。不得使用测试集答案或人工改写动态生成该问题的查询、检索候选或上下文；人工改写参考组除外，但只能用于该参考组的 Query。

## 3. 对照方法

在同一数据、索引、检索器、Top-K、上下文预算和回答模型下比较：

| 方法 | 检索输入 |
|---|---|
| Current | 当前问题原文 |
| History | 最近若干轮历史与当前问题，采用固定窗口和格式 |
| Rewrite | 用生成模型依据可见历史生成独立问题；记录提示词、模型和失败回退 |
| Human rewrite | 使用 QReCC 人工改写作为参考，不作为实际系统的可用输入 |
| 改进方法 | 根据开发集失败分析确定，例如按需重写或原始与改写 Query 联合检索 |

对话历史默认采用数据集提供的历史，实验中说明使用参考答案还是系统生成答案；主要对照采用同一历史，避免误差传播混入 Query 策略比较。可另做使用生成历史的端到端实验。话题切换、指代和省略等类型依据公开标注或预先定义的人工标注规则确定。

## 4. 指标与记录

- **检索**：在有可靠相关性标签时计算 Recall@K、MRR；明确相关性粒度、K、分母和缺失处理。缺失标注样本单独计数。
- **回答**：按数据语言及任务选择归一化后的 Exact Match、token F1 等指标，并人工抽样核对语义正确性。自动匹配不足以判断所有正确答案。
- **证据与引用**：检查引用 ID 是否存在，并对分层抽样人工判断回答是否被引用片段支持；报告标注规则、样本数及分歧处理。可选模型评分只能作为辅助，需标明模型和提示词。
- **效率**：记录各步骤延迟、总延迟分布、请求数、Token 用量、失败率及按实验时价格估算的成本；报告缓存、并发、硬件、服务地域和计费依据。供应商未返回用量时标注缺失或估算方式。
- **统计**：按同一问题配对比较，报告样本数、指标差值及按会话分组的 bootstrap 置信区间；小样本和标签不足时明确限制。

每次运行保存配置、代码版本、数据和索引清单、模型名称及版本、提示词版本、生成参数、随机种子、原始 Query、改写、候选、引用、回答、用量和错误。远程模型不保证完全确定性，因此复现实验要保留实际输出，不能仅依赖随机种子。敏感数据和密钥不得写入公开结果。

## 5. 实验步骤与验收

1. 对小样本逐条核查导入、证据映射与评分，形成数据质量报告。
2. 在开发集确定历史窗口、提示词和改进方案；冻结配置后运行测试集。
3. 运行所有基线与改进方案，保持共同条件；重写所需的额外模型调用计入成本。
4. 对改进方法做消融，按问题类型分析失败案例，并给出质量与成本取舍。
5. 发布可复现命令、配置和汇总；如许可允许，提供数据清单及人工标注，否则提供获取和重建方法。

阶段四最低验收：同一固定测试子集上，三种基线能完成端到端运行，能追溯每条结果，缺失证据和失败样本均有统计。阶段五最低验收：至少一个有明确假设的改进方法、对照、消融和局限分析；不以指标必须提升为完成条件。
