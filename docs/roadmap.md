# 开发计划与验收标准

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| 一：设计 | 架构、模型切换、数据与实验规范 | 文档明确流程、接口、限制和验收；可据此开始实现 |
| 二：工程基础 | 依赖、配置、模型接口、日志与测试 | Qwen API 和可配置兼容服务通过同一接口调用；错误和密钥处理可验证 |
| 三：基础 RAG | 文档导入、索引、多轮问答、引用、CLI/API | 小型知识库端到端运行，重启后索引和会话可用；证据不足有明确行为 |
| 四：基线评测 | 数据清单、证据映射、三种 Query 策略及评测 | 固定样本可重复运行并保留中间结果、指标和失败统计 |
| 五：研究改进 | 失败分析、改进、对照和消融 | 形成有证据支持的结果和局限，结果可以是不提升 |
| 六：效率优化 | 切分、Top-K、Embedding、重排和上下文预算实验 | 在受控条件下报告质量、延迟及成本，选择有依据的配置 |
| 七：部署交付 | 自部署模型、部署文档、测试与报告 | 目标服务器完成真实端到端验证并记录资源与限制 |

## 阶段二实施顺序

1. 建立 Python 项目、配置和测试入口，锁定或记录依赖版本。
2. 定义领域对象和生成、Embedding、Reranker 等端口；实现可替换适配器。
3. 实现 Qwen API 与通用 OpenAI 兼容服务配置；使用模拟服务测试协议、超时和失败处理，密钥存在时再运行真实连通性检查。
4. 建立日志、错误分类及最小 CLI，提供 `.env.example` 和使用说明。

真实 API 调用、数据下载与完整实验依赖网络、密钥、服务配额和预算；没有这些条件时先完成可离线验证的部分，并明确未验证项。实际部署也取决于服务器配置，不把设计当作已验证的生产能力。
